# CaboHealth 3.0 data inventory

Status: Draft — not release-approved

This inventory describes the planned 3.0/build 4 candidate: two public resources, one protected Client Resources surface for eligible existing in-person clients, and the isolated App Review sample. The separately hosted owner-only Staff Access portal remains an operational system outside the consumer binary and is reachable only by direct web URL. It is not an App Privacy submission or a completed production attestation. Items marked **PENDING** block release.

The public miniapps request no health information, require no account, and use no Firebase Analytics product, first-party analytics feature, advertising, purchase flow, user-generated-content submission, or sensitive permission. They have no native message bridge.

Client Resources requests no health information and offers no profile, free-text field, upload, advertising, checkout, subscription, in-app purchase, or paid digital tier. A valid code verifies existing-client eligibility; it is not a purchase credential.

The inspected signed 3.0/build 4 IPA’s exact FirebaseAuth privacy manifest maps **User ID** as linked to the user for **App Functionality** and **Other Diagnostic Data** as not linked to the user for **Analytics**; both entries declare no tracking. That Apple-selectable Analytics purpose is the FirebaseAuth SDK declaration, not evidence that the Firebase Analytics product is enabled: the product remains disabled and CaboHealth has no analytics feature. The next exact signed RC must confirm the same embedded mapping before the App Store Connect privacy answers are saved.

The public contractual baseline includes the [Firebase terms matrix](https://firebase.google.com/terms/), which places Cloud Firestore, Cloud Functions for Firebase, Firebase Authentication, and Firebase App Check under the Google Cloud Platform terms; the [Google Cloud Terms directory and Cloud Data Processing Addendum](https://cloud.google.com/product-terms); and the [Hostinger Data Processing Addendum](https://www.hostinger.com/legal/dpa). These public pages are reference material, not evidence that the exact production accounts accepted the applicable terms.
