# CaboHealth 3.0 data inventory

Status: Draft — not release-approved

This inventory describes the planned 3.0/build 10 candidate: an owner-managed catalog seeded with two CaboHealth-authored public resources, protected Client Resources, the isolated App Review sample, and a reviewed external-HTTPS capability. Builds 4–8 are obsolete-source history; build 7 reached EAS FINISHED without claimed App Store Connect processing, while build 8 was built, attested, uploaded, observed Ready to Submit, and available to the existing internal group before becoming obsolete for the WebView subframe fix. Build 9 is input-attested, aborted-pre-provider history and cannot authorize build 10. Current build-10 input/artifact/RC authority is absent. The separately hosted owner-only Staff Access portal remains outside the consumer binary. This inventory is not an App Privacy submission, physical-device valid-flow evidence, or a completed exact-RC attestation. Items marked **PENDING** block release.

Client Resources requests no health information and offers no profile, free-text field, upload, advertising, checkout, subscription, in-app purchase, or paid digital tier. A valid code verifies existing-client eligibility; it is not a purchase credential.

The inspected signed 3.0/build 4 diagnostic IPA’s exact FirebaseAuth privacy manifest maps **User ID** as linked to the user for **App Functionality** and **Other Diagnostic Data** as not linked to the user for **Analytics**; both entries declare no tracking. Builds 4–8 are obsolete for release, but remain valid historical evidence about their own bytes. That Apple-selectable Analytics purpose is the FirebaseAuth SDK declaration, not evidence that the Firebase Analytics product is enabled: the product remains disabled and CaboHealth has no analytics feature. The exact signed 3.0/build 10 RC must independently confirm the mapping before the App Store Connect privacy answers are saved.

The public contractual baseline includes the [Firebase terms matrix](https://firebase.google.com/terms/), which places Cloud Firestore, Cloud Functions for Firebase, Firebase Authentication, and Firebase App Check under the Google Cloud Platform terms; the [Google Cloud Terms directory and Cloud Data Processing Addendum](https://cloud.google.com/product-terms); and the [Hostinger Data Processing Addendum](https://www.hostinger.com/legal/dpa). These public pages are reference material, not evidence that the exact production accounts accepted the applicable terms.
